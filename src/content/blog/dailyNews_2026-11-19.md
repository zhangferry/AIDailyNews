### [如何在“不能出错”的系统里使用 AI Coding？分布式存储实践与边界](https://tech.meituan.com/2026/10/29/AI-Coding-IN-Distributed-Storage-System.html)

来源：美团 · 技术团队

发布时间：2026-11-17 14:19:53
![](https://p0.meituan.net/meituantechblog/9a74631daee8a14563f476bc3f9465001018168.jpg)
**美团基础技术部分享在分布式存储这类"不能出错"的系统中使用 AI Coding 的实践与边界：AI 能显著提速评审与排查，但比多写代码更重要的是让代码和结论经得起验证，设计背景判断仍需人来把关。**

* AI 评审擅长跨文件一致性检查、构造可执行证据、稳定识别常见竞态、发现被删代码与构建编排问题；但看不到运维流程与设计决策，会把有意为之（如正确性优先的 abort）误判为缺陷，其修复建议本身也需评审
* 提出四层互补证据体系：静态评审找候选、测试判真伪、运行时日志看现实是否发生；实测全仓 117 个疑似问题经 gtest 确认 36 条、证伪 3 条，还顺带暴露了 CI 自身缺陷
* AI Debug 应定位为假设生成器与验证助手，其解释无论多完整都不能直接当作根因结论，需警惕把单点事实当因果位置、把缓解效果当根因、围绕触发 case 做局部修补
* 落地建议：结论按测试确认/证伪/源码确认/未验证四档输出；"无问题"结论必须列出已检查路径；不用多 Agent 投票代替正确性判断；只给 AI 稳定的高层不变式而非全量文档

### [Agent 改了 40 个文件你才发现？用 Harness Hook 把止损写进架构](https://www.bestblogs.dev/article/d805a1e5ac?utm_source=rss&utm_medium=feed&utm_campaign=resources&entry=rss_article_item)

来源：BestBlogs.dev - 精选文章

发布时间：2026-11-17 08:45:00
![](https://image.jido.dev/20251127045410_4d44587a)
**文章提出 stop-line 框架，将 Agent 长任务的止损逻辑从 Prompt（数据面）上移到 Harness 生命周期钩子（控制面）：计数与拦截交给代码，判断与交接交给模型，从而防止范围失控和不可逆操作。**

* 针对三类典型失败：同一补丁换着写法反复重试、错误指纹漂移、改动从 3 个文件蔓延到 40 个以及 rm -rf 类不可逆命令；纯 Prompt 方案在需要止损时并不可靠。
* 双层架构分工明确：Hook 层做确定性计数与拦截，Skill 层做判断与交接；HANDOFF 交接文档中“已排除的假设”一节可让下一会话跳过已失败的方向，显著节省预算。
* 签名归一化通过正则统一十六进制、IP、路径、数字等表面形式，识别换汤不换药的循环重试。
* 线上实测成功拦截范围失控与不可逆操作，同时暴露预算停止被误解除、临时文件计入预算两个 Bug 并给出修复；守卫类插件建议默认项目级启用而非全局启用。

### [《Agent评测白皮书》系列02：商家 AI 助手的评测与优化闭环实践](https://tech.meituan.com/2026/11/17/Agent-Evaluation-White-Paper-02.html)

来源：美团 · 技术团队

发布时间：2026-11-17 14:19:53
![](https://p0.meituan.net/meituantechblog/1c1d9dd8cb5e604097bc6140e1cd8f95265956.png)
**美团《Agent评测白皮书》系列第二篇，以商家广告助手的每日巡检任务为贯穿案例，完整呈现业务 Agent 评测体系从 Benchmark 构建、评测器校准到错误分析驱动迭代的闭环实践。**

* 评测场景采用双路径构建：从业务 SOP 自顶向下拆解业务状态图保证核心流程覆盖，再从线上 Bad Case 自底向上补齐边界与回归，KA 每日巡检最终形成六类 41 个可执行 Task
* 成功标准从流程遵循 SOP、过程有据可依、输出可交付三方面拆解为 Rubric：可精确取证的交给确定性 Grader，语义判断交给 LLM Grader，并配套任务完成率、Pass@k、Pass^k 等五维指标
* 强调评测器自身需持续校准（自动回归、稳定抽检、触发复核三种机制），且"尺子变准"不等于"Agent 变强"，两者是独立迭代闭环
* 优化后瓶颈从"不会做"转为"不能稳定做对"（Pass^k 显著低于 Pass@k），并借助图灵平台将 Task 集、Evaluator、Pipeline 沉淀为可复用评测资产，支撑持续回归与模型选型

### [Photon：帮硅谷最火的 PA 接入 iMessage，450 万美元融资、4 个月收入涨 10 倍](https://www.bestblogs.dev/article/6c1db39557?utm_source=rss&utm_medium=feed&utm_campaign=resources&entry=rss_article_item)

来源：BestBlogs.dev - 精选文章

发布时间：2026-11-17 19:00:00
![](https://image.jido.dev/20251127045419_08d80bcb)
**Photon 通过构建 Agent 消息基础设施，让 Personal Agent 以 API 形式接入 iMessage、WhatsApp、邮件和电话，普通用户无需学习新系统即可使用，并凭借 450 万美元种子轮融资与 4 个月收入增长 10 倍完成商业验证。**

* 通用大模型在技术上虽可处理机器人任务，但训练成本高昂、实时性不足，不适合直接部署；具身智能需要“刚刚好”的专用模型高效执行物理操作。
* 端侧 Draft Model 快速执行日常任务，云端通用模型处理复杂长程任务与数字世界服务，两者协同构成完整的智能体系。
* 行业对高质量具身数据的定义尚未统一，盲目堆数据是浪费；预计未来一年技术路线将迎来第一波收敛，数据标准随之明确。
* 落地策略是先在具体场景中后训练以提升成功率，并配套工具链降低使用与微调成本，逐步从通用底座过渡到实际应用。
